本次为 Windows 连接稳定性与故障诊断更新，包含 1.9.2 的修复。

### 修复与改进

- 保护运行中实例正在使用的代理桥接，避免测速/健康检查因瞬时不可用而杀掉进程、替换端口或丢失引用计数。
- Mihomo 增加原端口有限恢复；代理退出日志包含错误输出。代理绑定丢失时明确报错，不再静默直连；拦截绕过代理绑定的启动参数。
- 通过可取消的 CDP 会话记录网络失败、HTTP 错误和渲染进程崩溃，关联实例、运行编号及实际内核版本。网络事件不保存完整 URL、Cookie、请求头或请求/响应体。
- 默认启用 JSON 文件日志和轮转，文件写入失败时保留内存日志，错误日志立即刷新；日志页显示读取/落盘失败，支持脱敏诊断包本地导出，不上传。
- 基础指纹自检增加页面/Worker 一致性检查，明确区分基础通过、不一致与未验证，不将版本号或参数下发当作完整伪装认证。

### 验证与限制

- 修复代码已通过本地受影响包测试、前端构建，以及 GitHub Windows 全量工作流的测试、检查和打包；本版本产物由 GitHub Actions 重新构建并校验。
- Chromium 148 独立测试实例验证了网络失败、HTTP 403、真实渲染崩溃记录与基础页面/Worker 一致性。
- Chromium 151 的额外 headless 测试未通过：时区、CPU 与期望不一致，webdriver 为 true。正常窗口启动路径与完整伪装能力仍未验证。本发布不包含或修改该指纹内核，也不宣称解决其兼容性。
- 本次修复已确认的连接风险并补齐诊断证据，不能据此认定所有历史断网或内核崩溃的唯一根因。

### 升级与日志

升级前备份已有环境数据；本发布不上传或迁移用户环境，不自动更换已配置的内核。不要在升级内核后未经验证反复降级复用同一用户数据目录。

旧默认日志配置首次迁移到配置版本 3 后启用文件日志；旧版本的默认关闭和手动关闭无法完全区分，仅匹配原默认路径、text 格式和未启用轮转的组合，自定义路径保持原设置。版本 3 后明确关闭文件日志保持关闭。

默认日志按 20MB/日期轮转，最多 5 个分片、最长 7 天；诊断包只在用户选择的位置本地保存。清空日志页只清内存列表，不删除磁盘历史。
