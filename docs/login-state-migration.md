# 登录态备份与迁移

本轮扩展基于 9adf168。目标是减少同机恢复、换设备及重装 Windows 后不必要的重新登录，不承诺绕过网站的会话过期、风控或设备绑定。

## 使用

1. 在新版 Ant Browser 中启动原实例，确认账号仍可正常访问。
2. 备份前从实例列表点击“停止”。应用关闭前也会尝试最后一次快照；直接关闭浏览器窗口只能使用最近一次周期快照，最多可能落后 30 秒。
3. 导出实例或创建全量备份时勾选“可迁移登录态”，设置至少 8 字符的迁移密码。备份可经现有本地、OpenList、S3 渠道保存。
4. 在目标 Windows 设备导入并输入原迁移密码。密码校验失败不会修改目标实例/数据库；全量恢复仍沿用现有合并语义，实例包可选覆盖或新建。
5. 首次启动实例时先不开页面，写入 Cookie 并回读核验，然后打开原标签页或配置的启动页。恢复失败保留待恢复文件并停止本次启动，不伪报完成；成功后消费一次性标记，之后不会重复回滚 Cookie。

迁移密码不保存在配置或日志中，丢失后无法从其他设备恢复加密快照。迁移前的旧备份不能凭空补出缺失密钥或 Cookie。自动定时备份及旧版直接导出接口未新增密码存储：跨设备登录态请使用本轮的交互式备份入口。

## 数据与加密

- 在现有实例生命周期内每 30 秒读取浏览器原生 `Storage.getCookies`，本机快照使用 Windows DPAPI 加密，不新增常驻进程。实例列表停止、应用退出和维护关闭前尝试最终快照；使用同一个实例操作锁避免旧快照覆盖最终快照。
- v2 迁移包以 Argon2id + AES-GCM 保护 Cookie 快照、捕获时间及用于恢复标签页的网页地址；版本/类型参与认证，防止把 Cookie 载荷误当旧主密钥。兼容旧 v1 传统 DPAPI 主密钥迁移包。
- 对原浏览器能正常读取的 App-Bound Cookie，通过原生浏览器接口读取和重写，不解密 App-Bound 系统密钥、不禁用浏览器加密。目标本机重新建立加密密钥；传统可迁移主密钥存在时兼容保留。
- 保留 HttpOnly、Secure、SameSite、优先级和可序列化 CHIPS 分区信息，跳过过期 Cookie；不把 session Cookie 延长成永久 Cookie。不透明分区 Cookie 无法安全重建时拒绝生成新快照，不降级成普通 Cookie。
- Local Storage、IndexedDB、扩展数据等仍随完整用户数据目录备份；未实现 sessionStorage 的跨进程恢复。已保存密码、通行密钥、硬件绑定令牌不保证可迁移。
- 普通备份同设备/同 Windows 用户可读取本机快照时，也会安排首次启动恢复。其他设备没有迁移密码时不假装已解决加密绑定问题。
- 全量备份的迁移组件纳入现有 manifest 完整性检查；密码解密发生在解压暂存目录，先校验再修改目标。迁移选项只加密新增迁移载荷，不是整个 ZIP 的加密开关；其他网站存储/配置仍可能含敏感数据，应保护整个备份。
- 日志只有阶段、实例 ID、数量、快照时间和不含凭据的错误；不记录 Cookie 名称/值、令牌、迁移密码、解密密钥或恢复标签页地址。

## 验证与边界

指定内核：`ungoogled-chromium_151.0.7922.137-1.1_windows_x64/chrome.exe`，全部使用临时目录与本地合成测试站点，不读取真实账号。

- 原生有界面内核的无启动窗口门控通过；Cookie 注入前没有页面目标。
- 原生隔离源/目标环境中迁移 HttpOnly 会话 Cookie 和持久 Cookie，目标 HTTP 服务器识别原会话；目标模拟无效 App-Bound 包装密钥时重新建立本机密钥，非目标 Local State 结构保留。
- 全量备份组件、manifest 校验、密码缺失/错误时不修改目标、恢复目录路由、网站存储保留、本机快照加密/解密和目录穿越拒绝有定向测试。
- 真实 React 组件在 1440/800 宽度验收：密码校验、错误密码保留重试、成功清空输入及内容不溢出。UI 绑定明确为模拟，不冒充完整 Wails E2E。

未在另一台物理设备或真正重装的系统上运行，未验证商业网站真实账号和实际 v20 数据库；不能把隔离目标测试等同于所有网站/内核的免登录保证。当前快照加密仅支持 Windows；Linux/macOS 保持明确不支持跨设备登录态迁移。正式安装包尚未构建发布。
